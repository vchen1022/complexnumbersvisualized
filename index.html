Complex Numbers.

The mathematics behind the imaginary.

Complex Numbers and the Complex Plane

A complex number is written as:

z = x + iy   x is the real part.   y is the imaginary part.
i is the imaginary unit, defined by i^2 = -1.

You can think of a complex number as a point on a 2D plane: the complex plane. The horizontal axis is the real axis, and the vertical axis is the imaginary axis. A point at (x, y) represents x + iy.

The modulus of z is its distance from the origin:   |z| = r = sqrt(x^2 + y^2)

The argument of z is the angle from the positive real axis:   arg(z) = theta

It is usually measured counterclockwise. The standard range is -pi to pi (or 0 to 2*pi). The argument tells you which direction the point lies in.

Basic Operations

1. Addition and Subtraction

Combine real parts with real parts and imaginary parts with imaginary parts, treating i like a variable.

Example:

(6 - 2i) + (-5 + 6i)
= (6 - 5) + (-2i + 6i)
= 1 + 4i

2. Multiplication

Multiply using the distributive property then substitute -1 for any instance of i².

Example:
(2 + 3i)(6 - 2i)
= 12 - 4i + 18i - 6i²
Replace i² with -1
12 + 14i - 6(-1)
= 12 + 14i + 6
= 18 + 14i

3. Conjugate Multiplication

The conjugate of a complex number a + bi is a - bi.
Multiplying a number by its conjugate eliminates the imaginary middle terms:
(a + bi)(a - bi) = a² + b².

Example:
(6 + 3i)(6 - 3i)
= 36 - 9i^2
= 36 - 9(-1)
= 45

4. Division

Multiply both the numerator and the denominator by the conjugate of the denominator to clear i from the bottom of the fraction.

Example:

8 + 4i4 + 2i  =  (8 + 4i)(4 − 2i)(4 + 2i)(4 − 2i)  =  32 − 16i + 16i − 8i²16 − 4i²  =  32 + 816 + 4  =  4020  =  2

Polar Form and Euler's Formula

Any complex number can be written in polar form:   z = r(cos(theta) + isin(theta)) = r * e^(itheta)

This comes from Euler's formula:   e^(itheta) = cos(theta) + isin(theta)

This formula says that e^(i*theta) is a point on the unit circle at angle theta. Multiplying by r scales it to distance r. So polar form separates a complex number into two independent pieces: how far (r) and which direction (theta).

Turning Pixels into Complex Numbers

A screen is a grid of pixels. Each pixel has a coordinate (px, py), where px increases to the right and py increases downward.

To treat each pixel as a complex number, you map its position to the complex plane:

  • Centre the plane: Subtract half the width and half the height so that the centre of the screen becomes the origin (0,0).
  • Scale by zoom: Divide by a zoom factor. A larger zoom means you see a smaller region of the complex plane, so details get magnified.
  • Flip the y-axis: On screen, y increases downward. In the complex plane, imaginary numbers should increase upward. So you negate the vertical coordinate.

The result is:

z = (px - width/2) / zoom + i * (-(py - height/2) / zoom)

Every pixel now corresponds to a unique complex number z. The zoom slider changes the scale factor, letting you zoom in and out of the complex plane.

Applying a Complex Function

You choose a function f(z). For each pixel, you compute:

w = f(z)

The output w is also a complex number. It has its own real part, imaginary part, modulus, and argument. Write it in polar form:   w = r * e^(I*theta)

  • r = |w| is the modulus of the output.
  • theta = arg(w) is the argument of the output.

Now you have two numbers per pixel: r and theta. These are what you use to colour the pixel.

Domain Colouring: Argument to Hue

What is Hue?

In the HSV colour model, hue is the colour itself. It is arranged on a circle:

  • 0 degrees (or 0 radians) is red.
  • 120 degrees is green.
  • 240 degrees is blue.
  • 360 degrees returns to red.

Because hue is circular, it is naturally measured as an angle.

Why Argument Controls Hue

The argument theta of the output is also an angle. It tells you the direction of the output vector in the complex plane. Since both hue and theta are circular, you can map one directly to the other.

For example:

  • If w points to the right, theta = 0. Hue becomes red.
  • If w points upward, theta = pi/2. Hue becomes a greenish-yellow.
  • If w points to the left, theta = pi. Hue becomes cyan.
  • If w points downward, theta = 3*pi/2. Hue becomes purple.

As theta changes, the colour rotates around the colour wheel. Because the argument wraps around every 2*pi, the colours also wrap seamlessly. This is why you see smooth rainbow spirals around zeros and poles. Changing theta changes hue because hue is defined as an angle on a colour circle. Rotating the output vector by any amount rotates the colour by the same amount.

Domain Colouring: Modulus to Brightness Rings

Why Modulus Controls Brightness

The modulus r is the distance of the output from zero. It tells you how large the output is. You want brightness to reflect this size. Large modulus means brighter; small modulus means darker.

However, complex functions can produce extremely large or extremely small values. If you mapped r directly to brightness, the image would blow out to white in some places and vanish to black in others. To compress the range, you use the logarithm:   log(r)

The logarithm turns multiplicative changes into additive changes. It tames exponential growth.

You also add a tiny number like 10^-12 inside the log to avoid taking the log of zero. At zeros of the function, r = 0, and log(0) is undefined. Adding 10^-12 keeps the calculation stable and makes the zeros appear very dark.

Why Rings Appear

Brightness is not mapped linearly to log(r). Instead, you use a cosine function:   brightness = 0.5 + 0.5 * cos(2 * pi * bands * log(r))

This oscillates between 0 and 1 as log(r) changes. As you move across the complex plane, r changes. When r changes by a certain multiplicative factor, log(r) changes by a fixed amount, and the cosine completes a full cycle. This creates concentric rings of light and dark around zeros and poles.

The bands slider controls the frequency multiplier. Higher bands means more rings packed together; lower bands means fewer, wider rings. This visualizes how quickly the magnitude of the function changes.

Handling NaN and Infinity

At some points, a complex function may give a result that is not a finite number:

  • NaN ("not a number") can occur from operations like 0/0.
  • Infinity can occur at poles, where the function divides by zero.

In domain colouring, these points are painted black. This highlights the singularities of the function, the places where it breaks or explodes.

The Functions and What They Show

z^3 - 1

A polynomial. It has three zeros, located at the cube roots of unity. Around each zero, the argument of the output rotates by 2*pi, so the hue cycles through the full colour wheel once. You see three black dots surrounded by colour spirals. There are no poles.

(z^2 - 1) / (z^2 + 1) (Default)

A rational function. It has zeros where the numerator is zero: z = +/- 1. It has poles where the denominator is zero: z = +/- i. At zeros, the function goes to zero and the argument is undefined, so it is black. At poles, the function explodes to infinity, so it is black. Around each zero and pole, the argument rotates, creating colourful spirals. This function is visually rich because it shows both zeros and poles.

sin(z)

The complex sine is defined as:

sin(x + iy) = sin(x)cosh(y) + icos(x)*sinh(y)

cosh and sinh are hyperbolic functions:   cosh(y) = (e^y + e^-y)/2,   sinh(y) = (e^y - e^-y)/2.

Unlike real sine, complex sine is unbounded. It grows exponentially as y moves away from zero.

Zeros occur along the real axis at multiples of pi.

The visualization shows oscillating zeros and rapid growth in the imaginary direction.

e^z

The complex exponential is:

e^(x + iy) = e^x * (cos(y) + i*sin(y))

  • The modulus is e^x, which depends only on the real part.
  • The argument is y, which depends only on the imaginary part.

The image shows horizontal colour bands (because hue depends on y) and exponential brightness growth to the right (because modulus depends on x).

It is periodic in the imaginary direction with period 2*pi.

There are no zeros.

1 / (z - 0.5i)

A simple pole at z = 0.5i. The function explodes to infinity there. The image is a single vortex of colour, with brightness rings tightening infinitely as they approach the pole.

Julia Set: z^2 + c

This is not domain colouring. It uses a different method entirely. See the next section.

The Julia Set

For the Julia set, each pixel is a starting value z0. You repeatedly apply the rule:

z(n+1) = z(n)^2 + c

where c is a constant complex number chosen by the sliders.

  • Escape radius: If at any point |z(n)| > 2, the sequence is guaranteed to escape to infinity. You stop iterating.
  • Iteration limit: You cap the number of iterations at 250. If the point does not escape within 250 steps, it is considered bounded and part of the Julia set.
  • Smooth escape-time colouring: If the point escapes, you colour it based on how many iterations it took. A naive integer count creates harsh bands. To smooth it, you compute a fractional iteration count using the formula: n + 1 - log2(log2(|z(n)|)) / log2(2) This produces a continuous gradient.
  • Interior: Points that never escape are coloured near-black. This represents the stable, invariant set of the function.
  • c sliders: Changing the real or imaginary part of c changes the shape of the Julia set dramatically. This is because the Julia set is highly sensitive to the value of c.

Complex Arithmetic Helpers

To compute f(z) for each pixel, you need to perform arithmetic on complex numbers. Instead of using a library, you write small helper functions for:

  • Addition: (a+bi) + (c+di) = (a+c) + (b+d)i
  • Subtraction: (a+bi) - (c+di) = (a-c) + (b-d)i
  • Multiplication: (a+bi) * (c+di) = (ac-bd) + (ad+bc)i
  • Division: (a+bi) / (c+di) = ((ac+bd) + (bc-ad)i) / (c^2 + d^2)

These are used to build the function definitions. For sin(z) and e^z, you also need the special formulas with cosh and sinh, which come from Euler's formula and the definitions of hyperbolic functions.
